# V0.19.4 — Returning User Avatar Rollout QA

## Goal

Make the new Soft 3D avatar feature visible to all existing learners automatically instead of relying on them to press Continue or discover Change Avatar manually.

## Eligibility

The rollout opens automatically only when both are true:

1. `digilians.studentName` already exists
2. `getAvatarProfile()` returns no valid current V2 avatar

A valid V0.19.3/V0.19.4 avatar skips the rollout entirely.

## Returning-user flow

`Open platform → Welcome loads → required Avatar Picker opens → choose → Save Avatar → Home`

No Study, Exam, QBank or Ranking state is reset.

## Required-mode behavior

During rollout:
- close button hidden
- initials fallback hidden
- backdrop click ignored
- Escape ignored
- Save disabled until one avatar selected
- underlying app remains inert
- body scroll remains locked
- one-time profile update badge visible

After Save:
- avatar stored as schema V2
- modal closes
- app becomes interactive again
- learner is routed to Home
- future reloads skip the rollout

## New learners

Normal onboarding is intentionally unchanged. New learners may still choose `Use Initials for Now`. The required flow applies only to returning saved-name learners without a valid current avatar.

## Interactive Chromium component QA

Production modal markup, CSS and `avatar-profile.js` were executed in Chromium with isolated localStorage.

Verified:
- required class applied
- close hidden
- initials fallback hidden
- ONE-TIME PROFILE UPDATE visible
- app-shell inert
- backdrop click cannot dismiss
- Escape cannot dismiss
- even programmatic close-button click cannot dismiss while required
- selecting Penguin 3D + Save stores schema V2 profile
- modal closes after successful Save
- app-shell inert state is removed

Result: PASS.

## Full localhost browser note

The environment's Chromium blocks direct localhost navigation with `ERR_BLOCKED_BY_ADMINISTRATOR`. Therefore no claim is made for a full localhost click-through from this runtime. The shipped local HTTP server is separately smoke-tested, and user verification remains `TEST-LOCAL.bat`.

## Automated Pre-Deploy

The shipped checker now validates:
- automatic returning-user rollout call in app startup
- required rollout mode
- hidden skip/close controls
- backdrop/Escape guards
- rollout badge/CSS
- valid current avatars preserve normal flow
- all prior SQL/Python/QBank/Analytics/Backup/Profile regressions

## Data protection

Only `data/changelog.json` changes among JSON files. Learning, exam, SQL, Python and Official QBank payloads remain byte-identical to V0.19.3.

## Deployment

`RUN-PREFLIGHT.bat → TEST-LOCAL.bat → GitHub LIVE`

Manual local test should use two browser states:

A. saved name + no avatar → required popup must appear immediately
B. saved name + valid avatar → popup must not appear
