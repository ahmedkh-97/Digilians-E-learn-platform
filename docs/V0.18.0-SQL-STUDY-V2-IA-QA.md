# V0.18.0 — SQL Study V2 & Learner/Admin Information Architecture

## Purpose

Two issues were addressed together:

1. SQL Study was visually clean but too compressed for first-time learning.
2. Curriculum/exam-production diagnostics were occupying learner-facing space.

## SQL Study V2

The SQL track contains:
- 8 sessions
- 34 Study sections
- 25 syllabus topics
- 520 production questions

Every Study section now contains:

1. What Is It?
2. Why Does It Matter?
3. Visual / mental model
4. Key Terms
5. Key Takeaways
6. Quick Check
7. Source Trace

## Grounding

`What Is It`, `Key Terms`, `Key Takeaways`, and Source Trace come from the existing SQL course production material.

The `Why` and visual teaching layer is explicitly labeled as a platform clarification based on the course concept.

Illustrative table values are not presented as source facts.

## Visual coverage

34/34 SQL Study sections contain a visual clarification.

Visual families include:
- concept flows
- comparison cards
- ER diagrams
- relational mapping
- normalization before/after
- Star Schema
- constraint checks
- DDL/DML/DQL groups
- SQL code blocks
- before/query/result tables
- aggregate transformation
- join visualization
- nested query flow
- set operation flow
- window calculation
- CTE
- pivot
- SQL control flow
- TRY/CATCH
- Views
- Stored Procedures

## Quick Checks

34/34 Study sections contain a Quick Check.

All 34 use unique question IDs from the existing course-derived SQL production banks.

The Quick Check source trace is retained.

Local save uses the existing Quick Check persistence system.

## Learner/Admin information architecture

### Learner view
The SQL module panel now shows:
- 8 Sessions
- 25 Topics
- 520 Practice Questions
- Final Ready
- learner-oriented `What You'll Learn`

### Internal QA view
The existing:
- Curriculum Readiness
- Syllabus Map & Coverage
- eligible-question counts
- coverage targets
- hard/external pool checks

are retained inside a collapsed `Platform Diagnostics` panel.

They are not removed from the exam engine.

## Final Exam learner card

The main learner card no longer displays implementation-level shortages.

It now reports:
- Questions
- Time
- Tracks Ready
- Ready / Coming Soon

The underlying readiness engine is unchanged.

## Chromium component QA

Real production CSS and the actual shipped SQL Study renderer were rendered in headless Chromium for:

- SQL Filtering

A 390px mobile component render was also checked.

Results:

This is component-level rendering, not a full application click-through.

## Assessment protection

V0.18.0 intentionally changes `data/learning.json`.

All other JSON payloads must remain byte-identical to V0.17.3 during final packaging.

That protects:
- SQL 520 question banks
- Python 520 question banks
- Official Junior 930
- Official Professional 1189
- exam blueprints
- production exams
- ranking configuration
