# V0.20.25 — Windows Local Start Fallback QA

Date: 2026-09-02
Baseline: V0.20.24 — Voucher Infrastructure
Scope: Local Windows launcher/tooling only. No assessment payload or learner schema changes.

## Behavior

- `START-LOCAL.bat` prefers Node.js when available: full Quick Check -> Node local server.
- When Node.js is unavailable, `START-LOCAL.bat` runs `tools/windows-basic-check.ps1` and starts `tools/windows-local-server.ps1` only after the basic check passes.
- The PowerShell server binds to loopback (`127.0.0.1`) only and uses no-cache response headers.
- `QUICK-CHECK.bat` provides a clearly labeled Windows basic compatibility check when Node is absent.
- `FULL-QA.bat`, `TEST-LOCAL.bat`, and `RUN-PREFLIGHT.bat` explicitly require Node.js 20+ instead of surfacing a command-not-found error.
- `LOCAL-TESTING.md` separates ordinary local use from developer QA requirements.

## Windows Runtime Acceptance Note

The automated build environment is Linux and does not provide Windows PowerShell or `cmd.exe`, so the actual `.bat` -> PowerShell execution path cannot be launched end-to-end inside this environment. The fallback is protected by static/behavioral contract tests, while final Windows acceptance is: extract the ZIP on Windows and double-click `START-LOCAL.bat` on a machine where `node` is not in PATH. Expected result: Windows Basic Check PASS, localhost starts on `http://127.0.0.1:4173/`, and the browser opens.
