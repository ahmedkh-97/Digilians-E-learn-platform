# V0.20.11 — Startup UX & Performance Guardrails QA

## Scope
This release is a stabilization/polish release. It does not change approved Study, Practice, Excel Full Track Exam, Official QBank, Ranking rules, or assessment content.

## Findings
- Startup entry controls were interactive before `loadData()` completed, creating a slow-network race into an incompletely initialized dashboard.
- Saved Dark Mode was applied by `app.js` after CSS/JS loading, allowing a first-paint light-theme flash.
- Current startup payload is acceptable; a large architectural split is not justified at this stage.

## Fixes
- `startBtn` and `continueUserBtn` are disabled in static HTML and only enabled after core startup data is ready.
- Saved `digilians.theme` is applied before the main stylesheet to reduce theme flash.
- A permanent Pre-Deploy performance gate now protects startup dependency count and payload budgets.
- Startup recovery remains independent for load failure and timeout cases.

## Startup Performance Snapshot
- Startup dependency set: 37 files.
- Raw payload: ~2744.9 KB.
- Gzip estimate: ~403.3 KB.
- Budgets: <= 40 startup dependencies, <= 3072 KB raw, <= 450 KB gzip estimate.
- `data/learning.json` parse benchmark in Node: median ~3.24 ms, p95 ~4.82 ms.

These are guardrail measurements, not browser/network SLA claims. Real page-load time varies by browser, device, cache, network, and hosting compression.

## Permanent Regression Guard
`tests/platform-ux-performance.test.mjs` verifies:
1. Entry CTA is inert until platform data is ready.
2. Saved theme is applied before the main stylesheet.
3. Startup dependency count/raw/gzip budgets stay within limits.
4. Independent startup recovery remains present and bounded.
5. Pre-Deploy permanently executes this gate.

The test resolves project paths from its own location and was verified from outside the project working directory.
