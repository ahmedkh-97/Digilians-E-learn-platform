Digilians-E-learn-platform

V0.19.0 — Progress Backup/Restore & Private Error Monitoring QA

Scope

This is the final planned infrastructure pass before Excel curriculum production.

Two capabilities are added:

  1. local Progress Backup / Restore
  2. private client Error Monitoring inside the existing Admin Analytics dashboard

No educational content change is intended.

Progress Backup

Included learner keys

Only an explicit allowlist is exported.

Examples:

  • digilians.studentName
  • digilians.playerId
  • digilians.results
  • digilians.examProgress
  • digilians.studyProgress
  • digilians.quickChecks
  • digilians.officialQbank
  • ranking view preferences

Explicitly excluded

Not exported:

  • digilians.analyticsAdmin.session
  • digilians.analytics.visitorId
  • analytics session ID
  • update-dismissal state
  • What’s New seen version

The backup system never enumerates arbitrary localStorage keys into the backup.

Integrity

Backup schema:

  • format = digilians-progress-backup
  • schemaVersion = 1
  • platformVersion
  • exportedAt
  • data
  • SHA-256 checksum

Import validates:

  • JSON object
  • format
  • schema version
  • allowed keys
  • expected JSON object/array types
  • theme/ranking scalar values
  • 5 MB size limit
  • checksum

Merge behavior

Merge:

  • deduplicates results by client attempt ID
  • deduplicates pending attempts
  • unions Study completed sections
  • keeps later Study/Quick Check state where timestamps exist
  • unions Official QBank reviewed/bookmarks/mistakes
  • merges Official QBank answers
  • keeps an existing active exam resume instead of silently replacing it

Replace behavior

Replace clears/replaces only learner allowlist keys.

Analytics/Admin/Update state is not removed.

Restore safety snapshot

Immediately before applying a restore, current learner progress is downloaded as:

digilians-before-restore-YYYY-MM-DD.json

Private Error Monitor

Uses the existing analytics_events table with:

event_type = app_error

No new Supabase table is required when the V0.18.3 Analytics schema already exists.

Captured categories

  • JavaScript errors
  • resource load errors
  • unhandled promise rejections
  • explicitly reported handled startup/data-load failures

Safe metadata only

Stored error metadata:

  • kind
  • sanitized message
  • source filename only
  • line
  • column
  • phase
  • route/version already provided by the event envelope

Never intentionally stores:

  • stack trace
  • learner name
  • learner answer
  • email
  • full URL
  • IP address

Redaction

Safe error message removes:

  • email addresses
  • URLs
  • UUIDs
  • long numeric identifiers
  • unusually long quoted values

Maximum message length: 180 characters.

Flood protection

Per browser session:

  • max 20 reported errors
  • same signature deduplicated for 60 seconds

Local QA isolation

localhost / 127.0.0.1 do not submit Analytics or Error Monitor events.

Platform Health dashboard

New private Admin panel:

  • Error Events
  • Affected Sessions
  • Error-Free Sessions
  • Recent safe errors

The existing Today / 7 Days / 30 Days / All Time filter controls the health metrics too.

Automated Pre-Deploy

The shipped checker verifies:

  • backup module exists and cache version matches
  • all Backup/Restore DOM references exist
  • backup validation/checksum path
  • Analytics/Admin/Update keys excluded
  • Merge result/study behavior
  • safe error-message redaction
  • error health aggregation
  • app/custom error instrumentation
  • no error stack usage
  • error report rate limit / dedupe constants
  • Backup/Error Monitor CSS
  • all prior SQL/Python/QBank regressions
