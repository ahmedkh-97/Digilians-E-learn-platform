# V0.18.3 — Private Platform Analytics V1 QA

## Scope

This release adds anonymous product analytics plus a private Admin dashboard.

It does not change educational curriculum, question banks, answers, exam blueprints or ranking calculations.

## New files

- `assets/js/analytics.js`
- `supabase/ANALYTICS-SCHEMA.sql`
- `supabase/ADD-ANALYTICS-ADMIN.sql`
- `supabase/ANALYTICS-SETUP-GUIDE.md`

`data/changelog.json` is updated for the new release.

## Tracking identity model

`visitor_id`
- random UUID
- stored in localStorage
- persists across normal returns on the same browser

`session_id`
- random UUID
- stored in sessionStorage
- new for a new tab/browser session
- survives a normal page refresh in that same tab

This gives practical approximate Visitors / Sessions without student accounts.

## Fail-safe behavior

Analytics is non-blocking.

If the Supabase analytics table is unavailable:
- event submission fails silently after one console warning
- tracking pauses briefly
- Study / Practice / Exams / Ranking continue normally

Localhost / TEST-LOCAL never submits analytics events.

## Privacy sanitizer

The event metadata sanitizer blocks variants of:
- student name
- learner name
- email
- answer / answers
- response / responses
- IP / IP address
- password

Only short primitive metadata fields are accepted.

Automated payload regression confirms blocked fields do not survive.

## Supabase security

### analytics_events

Anonymous and authenticated browser roles:
- INSERT allowed

Anonymous:
- SELECT not granted

Authenticated:
- SELECT privilege exists but RLS returns rows only when:
  `public.is_analytics_admin()` is true

No browser UPDATE / DELETE policy exists.

### analytics_admins

Contains the approved Admin email allowlist.

Authenticated SELECT is also protected by the same admin helper.

### is_analytics_admin()

SECURITY DEFINER helper compares the authenticated JWT email against the allowlist.

No service-role key is shipped to the client.

## Admin Auth flow

The client uses the Supabase Auth password token endpoint with the public publishable key.

After login:
1. access/refresh token is saved in the Admin session storage key
2. the app queries the protected `analytics_admins` endpoint
3. RLS must return the approved email row
4. only then does the Profile Analytics button become visible

A signed-in but non-allowlisted Supabase user is rejected.

## First-time Admin entry

Append:

`?admin=analytics`

to the GitHub Pages URL.

This only opens the login modal.

It is not an authentication bypass.

## Deployment

1. Run Supabase analytics schema.
2. Create private Auth Admin.
3. Add its email to the allowlist.
4. `RUN-PREFLIGHT.bat`
5. `TEST-LOCAL.bat`
6. Upload V0.18.3 to GitHub LIVE.
7. Open LIVE `?admin=analytics` and verify the real dashboard.
