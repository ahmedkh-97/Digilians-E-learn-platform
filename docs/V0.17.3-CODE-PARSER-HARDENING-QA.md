# V0.17.3 — Code Parser Hardening & Technical QA

## Why this release exists

V0.17.2 correctly introduced a universal code presentation layer, but local review exposed parser fragmentation in Python questions whose source text lost indentation during PDF extraction.

Examples observed:
- only the closing `]` becoming a code block;
- `if` being shown in a code block while its body remained heading text;
- `else:` becoming a separate code card;
- Pandas/lambda code choices being rendered as normal answer text.

V0.17.3 fixes the parser rather than patching individual question IDs.

## Parser strategy

Python parsing now keeps state across consecutive lines.

A Python program starts when a line matches a supported Python construct and continues while the following lines remain code or are required by open brackets.

Recognized constructs include:
- assignments and augmented assignments;
- tuple/destructuring assignments;
- control-flow statements;
- simple statements such as `break` and `continue`;
- function/class definitions;
- common Python expressions and method calls;
- list/dictionary continuations.

A clear prose line closes the program block.

## Bidi/source protection

The Professional Q55 stored source contains U+202B/U+202C around an Arabic question mark.

V0.17.3:
- removes the invisible direction controls from `displaySource`;
- does not modify the JSON source string;
- does not replace the visible Arabic `؟` with an English `?`.

This is deliberate source preservation.
