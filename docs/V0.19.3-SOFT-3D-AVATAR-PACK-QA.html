V0.19.3 — Soft 3D Avatar Pack QA

Reason for release

V0.19.2 implemented the Avatar system correctly but used approximate SVG character drawings.

The requested visual target is a polished Soft 3D cartoon avatar pack with human and animal characters.

V0.19.3 replaces the visual assets while preserving the existing profile system.

Production catalog

16 local WebP assets.

Boys — 4

  • boy-3d-1.webp
  • boy-3d-2.webp
  • boy-3d-3.webp
  • boy-3d-4.webp

Girls — 4

  • girl-3d-2.webp
  • girl-3d-3.webp
  • girl-3d-4.webp

Animals — 8

  • bear-3d.webp

  • koala-3d.webp
  • rabbit-3d.webp
  • lion-3d.webp
  • sloth-3d.webp

Every production avatar asset is 256 × 256 WebP.

Renderer

avatar-profile.js now renders local <img> assets.

No runtime image generation is used.

No image CDN is used.

The compatibility export avatarSvg() remains available internally but now aliases the image markup renderer; production UI uses the image asset catalog.

Filters

  • All = 16
  • Boys = 4
  • Girls = 4
  • Animals = 8

Internal storage categories remain:

  • male
  • female
  • neutral

This preserves the existing profile/backup structure without exposing category information to Analytics.

Migration

Avatar schema is bumped to version 2.

Previous V0.19.2 avatar selections used different SVG IDs.

Those records are intentionally treated as unselected so the learner sees the new Soft 3D picker once and chooses a correct new character.

No Study/Exam/QBank progress is affected.

Visual asset QA

A 4 × 4 contact sheet was generated from the final production crops and inspected.

Verified:

  • clean circular/pastel avatar backgrounds
  • no labels included inside asset crops
  • all character faces remain centered
  • no neighboring avatars enter another crop
  • Boy/Girl/Animal identities remain visually distinct
