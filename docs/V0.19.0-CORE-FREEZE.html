Freeze rule

During Excel intake / production, do not redesign or restructure the core unless one of these is true:

  1. a reproducible production bug blocks learning or exams
  2. data/content integrity is at risk
  3. security/privacy requires a change
  4. Excel exposes a genuinely reusable platform capability that cannot be implemented safely inside the existing architecture

Cosmetic preferences should be batched rather than interrupting curriculum production.

Release workflow after freeze

For normal content releases:

  1. work from the latest stable ZIP
  2. preserve existing assessment/QBank payloads unless the release explicitly targets them
  3. run shipped Pre-Deploy
  4. run TEST-LOCAL.bat
  5. verify changed content/renderer areas
  6. upload directly to GitHub LIVE after local approval
  7. use Live Update / What’s New for open users
