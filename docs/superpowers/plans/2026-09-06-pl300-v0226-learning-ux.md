# PL-300 V0.22.6 Learning UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to execute this plan. Follow TDD for every behavior change and `superpowers:verification-before-completion` before any completion claim.

**Goal:** Ship V0.22.6 as a source-faithful PL-300 learning upgrade: clearer interaction/progress UX, a reference-vs-answer structured layout, delayed retries, end-of-part review, smarter part cards/resume, better Arabic explanation presentation, and a complete 0.22.6 cache identity.

**Architecture:** Keep startup code small. Put retry scheduling and part-learning calculations in a new pure lazy PL-300 module, keep rendering in the existing lazy PL-300/native modules, and use `app.js` only as the route/controller that reads persisted state, saves attempts, advances navigation, and renders models. Extend the existing Voucher storage schema compatibly rather than introducing a second storage key. Preserve all existing scoring fields and source-bank data.

**Tech Stack:** Vanilla JavaScript ES modules, HTML/CSS, localStorage, Node 22 `node:test`, GitHub Actions, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-09-06-pl300-v0226-learning-ux-design.md`

### 1.3 Implement the smallest pure module

Recommended normalized shape:

```js
export const PL300_RETRY_DELAY_TRANSITIONS=4;

export function normalizePl300LearningState(raw={}){
  const parts={};
  for(const [partId,value] of Object.entries(raw?.parts||{})){
    parts[String(partId)]={
      transitionSerial:Math.max(0,Number(value?.transitionSerial)||0),
      pending:(Array.isArray(value?.pending)?value.pending:[])
        .map(normalizePendingItem)
        .filter(Boolean),
      updatedAt:value?.updatedAt||null
    };
  }
  return {version:1,parts};
}
```

Pending item shape:

```js
{
  questionId:'q4',
  dueAtSerial:4,
  deferToPartReview:false,
  updatedAt:'2026-09-06T...Z'
}
```

Keep time optional/injectable in pure functions where deterministic tests need it. Do not use DOM/localStorage in this module.
