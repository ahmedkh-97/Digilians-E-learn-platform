# V0.18.2 — Live Update & What’s New System QA

## Goal

Users may keep GitHub Pages open for hours while new platform versions are deployed.

V0.18.2 adds a persistent update layer so future releases can be detected without asking learners to repeatedly hard-refresh the site.

## Architecture

New independent module:

`assets/js/update-manager.js`

The update manager loads separately from `app.js`.

This keeps update detection independent from normal application rendering.

Release notes:

`data/changelog.json`

Version source of truth for live detection:

`VERSION.txt`

Installed build version:

`index.html → data-build-version`

## Update check

The manager checks on:
- startup
- every 5 minutes
- browser returning online
- tab visibility/focus after the recheck threshold

`VERSION.txt` is requested with:
- a timestamp query
- `cache: no-store`
- no-cache headers

Semantic version comparison is numeric:
- 0.18.2 > 0.18.1
- 0.19.0 > 0.18.9
- 1.0.0 > 0.99.99

## No forced reload

Detecting a new version only creates a notification.

The page never reloads automatically.

The learner chooses `Update Now`.

## Active exam protection

`app.js` publishes:

`window.__DIGILIANS_EXAM_ACTIVE__`

and dispatches:

`digilians:routechange`

When `examView` is active:
- the update remains visible
- Update Now becomes disabled
- label becomes `Available After Exam`
- message explicitly says the attempt will not be interrupted

When the learner reaches `resultView`:
- the update is shown again even if it was temporarily dismissed
- Update Now becomes enabled

## Update action

Update Now:
- clears Cache API entries if present
- does not call `localStorage.clear()`
- does not call `localStorage.removeItem()`
- navigates to the same path using:
  `?updated=<latest>&_=<timestamp>`

The unique URL forces a fresh index request.

The new index then points to versioned CSS/JS assets.

## What’s New

Automatic:
- shown once per installed build
- suppressed when a newer update is already waiting
- not opened automatically during an active exam

Seen key:

`digilians.whatsNew.seenVersion`

Manual entry points:
- Profile
- Footer

Recent release history is read from `data/changelog.json`.

## Chromium interaction regression

The real update manager and production CSS were executed in headless Chromium with controlled mocked version responses.

### Installed-version case
Current build: 0.18.2  
Remote version: 0.18.2

Verified:
- Update banner hidden
- What’s New opens automatically
- Modal displays V0.18.2
- Got it stores `digilians.whatsNew.seenVersion = 0.18.2`
- Modal closes

Result: PASS.

### Future-version case during exam
Current build: 0.18.2  
Remote version: 0.18.3  
Exam active: true

Verified:
- Update banner visible
- deferred exam state active
- Update Now disabled
- button label = `Available After Exam`
- title explains that the exam must finish first
- What’s New does not auto-open over the exam

Result: PASS.

### After exam completion
A `digilians:routechange` event to `resultView` was dispatched.

Verified:
- Update Now enabled
- button label returns to `Update Now`
- title becomes `New Update Available — V0.18.3`
- footer update indicator becomes visible
- What’s New details can show V0.18.3

Result: PASS.

## Automated Pre-Deploy coverage

The shipped Pre-Deploy checker validates:
- update manager file exists
- changelog exists and parses
- changelog latest = VERSION.txt
- current release is present
- update-manager cache version = VERSION.txt
- 5-minute check interval
- semantic version comparisons
- update URL generation
- no-cache version fetch wiring
- exam-safe deferral wiring
- absence of localStorage clear/remove operations
- update UI DOM IDs
- update CSS components

## Existing data protection

V0.18.2 adds one new JSON file:

`data/changelog.json`

All JSON files that existed in V0.18.1 are required to remain byte-identical.

This protects:
- learning content
- SQL/Python banks
- Official QBank
- exams/blueprints
- ranking-related payloads

## First deployment limitation

An already-open V0.18.1-or-older tab cannot execute code that did not exist when it loaded.

Therefore, after deploying V0.18.2, existing users need one manual refresh.

Once their tab has loaded V0.18.2+, future versions can be detected automatically.

`RUN-PREFLIGHT.bat → TEST-LOCAL.bat → GitHub LIVE`

No GitHub staging repository is required.
