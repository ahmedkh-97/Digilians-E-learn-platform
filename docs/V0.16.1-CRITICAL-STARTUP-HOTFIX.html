V0.16.1 — Critical Startup Hotfix

What broke

V0.16.0 introduced the Python Study V2 Quick Check interaction.

Inside renderPythonStudySection(), the outer Quick Check forEach was accidentally closed with one extra ).

Broken form:

article.querySelectorAll(".python-quick-check").forEach(check=>{
  ...
}));

Correct form:

article.querySelectorAll(".python-quick-check").forEach(check=>{
  ...
});

Because assets/js/app.js is loaded as:

<script type="module" src="assets/js/app.js"></script>

the syntax error prevented the main module from loading. That stops the application bootstrap and makes the whole platform appear frozen/stopped.

Why V0.16.0 validation incorrectly passed

The previous release process relied on:

node --check assets/js/app.js

In this runtime that check did not reproduce the browser’s ES-module parser mode.

The defect is correctly detected by:

node --input-type=module --check < assets/js/app.js

V0.16.1 now uses the ES-module form for every JavaScript file.

New regression gates

The release now has three JavaScript gates:

  1. ES-module syntax
    • 11/11 JavaScript files parsed as modules.
  2. Startup runtime simulation
    • the complete app.js module and imports initialize successfully against the platform data.
  3. Python Study V2 render simulation
    • the actual renderPythonStudySection() renderer was executed across all 75 Python Study sections.
    • 75/75 rendered successfully.

Content integrity

The hotfix changes application code only.

Assessment data is preserved:

Browser environment note

The container’s Chromium is administratively blocked from opening local HTTP/file URLs, so a full visual browser click-through cannot be claimed. The startup module and Study renderer were executed directly through runtime simulations, which exposed and verified the exact failure that static QA had missed.
