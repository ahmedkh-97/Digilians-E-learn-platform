# Digilians E-Learn — Private Analytics Setup

The platform code is ready, but Supabase must be prepared once before analytics starts collecting data.

## 1. Create the Analytics tables and RLS

Open:

Supabase Dashboard → your `digilians-e-learn` project → SQL Editor → New query

Paste and run:

`supabase/ANALYTICS-SCHEMA.sql`

Expected final result:

`Analytics schema ready`

## 2. Create your private Admin Auth user

Open:

Supabase Dashboard → Authentication → Users → Add user

Create one user using the email/password you want to use for the private dashboard.

Use an email only you control.

If the dashboard offers an auto-confirm / confirm email option, create the user as confirmed so password login works immediately.

## 3. Add that email to the Analytics allowlist

Open:

`supabase/ADD-ANALYTICS-ADMIN.sql`

Replace:

`YOUR-ADMIN-EMAIL@example.com`

with the exact lowercase email used for the Supabase Auth user.

Run the SQL.

## 4. Upload V0.18.3 to GitHub Pages

After the normal local test, upload the V0.18.3 project files.

Anonymous analytics starts automatically for users who load V0.18.3+.

## 5. Open the private dashboard the first time

Use your normal GitHub Pages URL and add:

`?admin=analytics`

Example pattern:

`https://YOUR-GITHUB-PAGES-URL/?admin=analytics`

The private Analytics Login appears.

Sign in with the Supabase Auth email/password created in step 2.

After successful verification:
- `Private Platform Analytics` becomes visible in your Profile drawer.
- Your admin session is saved on that browser.
- Future visits can open Analytics directly from Profile.

## Security model

Anonymous users:
- can INSERT anonymous analytics events
- cannot SELECT analytics events
- cannot read the analytics admin allowlist

Approved authenticated admin:
- can SELECT analytics events
- can read the allowlist row needed to verify admin access

The browser never receives a Supabase secret/service-role key.

## What is collected

- random visitor ID stored in localStorage
- random session ID stored in sessionStorage
- route/page view
- course/track/module/exam IDs when relevant
- platform version
- event type
- limited non-personal metadata
- timestamp generated by Supabase

## What is not collected

- learner name
- learner email
- IP address by application code
- exact location
- browser fingerprint
- question answers
- passwords
- exam answer payloads

## Accuracy note

Unique Visitors are browser/device approximations because students do not have accounts.

Clearing browser storage or using another browser/device creates a new anonymous visitor ID.

Anonymous public analytics can also be intentionally spoofed by a technically determined user. The dashboard is intended for practical product-usage insight, not audited billing/security telemetry.


## V0.18.4 — one-time historical version backfill

If Analytics was already collecting data on V0.18.3 and the dashboard showed `Unknown` under Version:

1. Deploy V0.18.4 first.
2. Open Supabase → SQL Editor.
3. Run:

`supabase/BACKFILL-ANALYTICS-VERSION-V0.18.4.sql`

This changes only Analytics rows whose `platform_version` is exactly `unknown`.

They are assigned `0.18.3` because Analytics did not exist before V0.18.3.

Future V0.18.4+ events use the corrected shared build-version resolver automatically.
